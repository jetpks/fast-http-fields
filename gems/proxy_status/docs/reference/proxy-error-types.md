# The proxy error type registry

The definitive page for `Fast::ProxyStatus::ERRORS` and the four lookups.

## The registry as data

§2.3 "lists the proxy error types defined by this document"; §3: "IANA has created the 'HTTP Proxy-Status Parameters' registry and the 'HTTP Proxy Error Types' registry … and has populated them with the types defined in Sections 2.1 and 2.3 respectively".

The gem pins the table at publication as frozen data — 32 entries in document order, each a frozen Hash of the three fields the registry's template names; unknown names pass through the field untouched, so a future registration never breaks an old gem version.

The two prose recommended statuses are the RFC's own text, verbatim; the descriptions of the entries live in the corpus's §2.3 and are not duplicated in the docs — the table carries the registry's data fields.

## The lookups

One table: `registered?` (bool, false for unknown), `recommended_status` (Integer or the RFC's prose, nil for unknown), `response_only?` (bool, false for unknown), `extra_parameters` (frozen Hash, {} for "None", nil for unknown):

```ruby
Fast::ProxyStatus.registered?("dns_timeout")                    # => true
Fast::ProxyStatus.registered?("vendor_error")                   # => false
Fast::ProxyStatus.recommended_status("http_request_denied")     # => 403
Fast::ProxyStatus.recommended_status("vendor_error")            # => nil
Fast::ProxyStatus.response_only?("connection_read_timeout")     # => false
Fast::ProxyStatus.extra_parameters("dns_error")
# => {"rcode" => "String", "info-code" => "Integer"}
```

## The recommended status and the response-only flag

The recommended status is a SHOULD for the sender: "Each proxy error type has a recommended HTTP status code. When generating an HTTP response containing the error, its HTTP status code SHOULD be set to the recommended HTTP status code. However, there may be circumstances … when another status code might be used". The gem never enforces it — the registry is advisory data.

The response-only flag's semantics: "Proxy error types that are registered with a 'Response only generated by intermediaries' value of 'true' indicate that they can only occur in responses generated by the intermediary. If the value is 'false', the response might be generated by the intermediary or an inbound server".

§2.1.1's specificity advice: "When sending the error parameter, the most specific proxy error type SHOULD be sent, provided that it accurately represents the error condition".

## Extra parameters

"Proxy error types can also define any number of extra parameters for use with that type. Their use, like all parameters, is optional. As a result, if an extra parameter is used with a proxy error type for which it is not defined, it will be ignored" — the table is advisory; the field preserves every parameter whatever the table says (see [Why diagnostics preserve unknown members](../explanation/diagnostic-leniency.md)).

## Unknown and future error types

The passthrough contract:

```ruby
field = Fast::ProxyStatus.parse("ExampleCDN; error=vendor_error")
field.first.error  # => #<Fast::SFV::Token "vendor_error">
field.to_s         # => "ExampleCDN;error=vendor_error"
```

§2.4's registration procedure: Expert Review, the template fields, the response-only guidance: "If the proxy error type might occur in responses that are not generated by the intermediary … the 'Response only generated by intermediaries' should be 'false'".

## How the registry is pinned

`test/fast/proxy_status/registry.rb` freezes the 32 names in document order, every entry's three fields, the deep-frozen property, the two prose statuses verbatim, the lookups' unknown answers, and the never-gates-a-parse proof (131 lines). The registry is data the tests freeze, not behavior the gem enforces.
